# DSH 插件性能分析器

用于记录 DSH 插件挂载后的 Cordis 生命周期事件，并在设置页面展示插件启动性能。

## 功能

- 区分 DSH 内置插件和用户自己安装的插件
- 扣掉子条目之后的插件自身耗时，容器条目不参与「最慢插件」排名
- 记录插件依赖等待时间，并指出最后就绪的那个依赖
- 记录插件激活耗时
- 区分成功、失败、进行中和未完成状态
- 支持按插件名称搜索
- 展示诊断信息
- 导出性能快照 JSON
- 通过 Host Remote 接口读取性能快照

## 当前覆盖范围

当前版本属于部分覆盖模式：

- 只记录 Profiler 加载之后发生的事件
- 不包含 Profiler 加载之前的启动事件
- 不包含模块解析和导入耗时
- 不包含没有 Loader 条目的 Fiber
- 不代表整个 Profile 的冷启动耗时
- 暂不计算完整关键路径

## 面向普通用户

### 适合哪些用户？

本插件面向希望了解 DSH 插件启动情况的普通用户，包括：

- 想查看哪些插件启动较慢的用户
- 想排查插件启动失败或卡顿问题的用户
- 想比较插件依赖等待时间和自身激活耗时的用户
- 想了解当前 DSH 插件运行状态的用户

普通用户不需要了解 TypeScript、Cordis 或 Remote 接口，也不需要修改插件代码。

### 如何打开？

启动 DSH 后，依次进入：

```text
设置 → 插件 → 性能
```

进入“插件启动性能”页面后，插件会自动读取当前 Host 的性能数据。

### 如何确认插件已经安装？

如果能够看到“插件启动性能”页签和卡片，说明本插件已经被 DSH 识别并成功加载。

如果完全看不到该页签，才需要检查插件是否安装，以及当前 Profile 是否已经加载本插件。

### 页面可以看到什么？

- 最慢的插件，以及它自己花掉的时间
- 有效样本数、失败数和本次观测窗口
- 每个插件的自身耗时、激活总耗时和依赖等待时间
- 插件启动成功、失败、进行中或提前结束的状态
- Host 运行时诊断信息
- 按插件名称搜索和筛选的结果

### 「自身耗时」和「激活」有什么区别？

「激活」是这个条目从开始加载到完成的全部时间。如果它是一个容器（页面上标着
「容器」），这段时间里绝大部分其实花在它装的那些子插件上。

「自身耗时」把子条目占掉的时间扣掉之后剩下的部分，才是这个条目自己的开销。想知道
「谁拖慢了启动」，看这一列。容器条目不会参与「最慢插件」的排名，否则真正慢的那个
插件会被它盖住。

子条目缺少计时时，这一列显示成 `≤ 12 ms`，表示真实值只会更小，不会更大。

### 「等待依赖」下面那个箭头是什么意思？

箭头指向最后一个就绪的依赖，也就是把这个插件从等待里放出来的那一个。等待时间长
不代表这个插件慢——它只是在空等，真正该看的是箭头指的那个。

如果这行文字是灰的斜体，说明归因存疑：这个依赖就绪之后过了很久这个插件才开始加
载，真正卡住它的东西可能没有被观测到。

### 为什么列表里有一百多个我没装过的插件？

DSH 本身是“万物皆插件”的 Harness：它自己的会话、模型、工具、界面等能力都是以
Cordis 插件的形式装载的。当前 `web` Profile 的两个自带 Bundle
（`@deepseek-ai/dsh-base` 和 `@deepseek-ai/dsh-web-app`）合计插入约 135 个条目，
它们和你自己安装的插件跑在同一棵加载树上。

这些内置插件才是 DSH 启动耗时的主要构成，所以本插件不会把它们藏起来。页面提供
“全部 / 我装的 / DSH 内置”三个归属筛选：默认停在“全部”，因为要回答的第一个问题是
“谁最慢”，而不是“谁是我的”。表格里“我装的”插件会被高亮标出。

### 我装的插件为什么没出现在列表里？

本插件只记录**实际运行过**的插件。`D:\DSH\Plugin` 目录下存在、但当前 Profile 没有
加载的插件不会出现；已加载但在 Profiler 挂载之前就完成启动的插件，也可能只留下
不完整的记录。它不是插件目录扫描器，也不是已安装插件清单。

### 归属是怎么判定的？

读取当前 Profile 的 `package.json`：`dsh.profile.bundles` 里列出的 Bundle 层，凡是
出现在 `dependencies` 中的都是你自己装的（pnpm 会把外部插件写进去），其余从 DSH
安装目录解析的就是内置。判定不出来时标为“未判定”，不会猜。

如果页面顶部提示“无法判定插件归属”，说明没能读到 Profile 清单，此时会显示全部
条目——采集本身不受影响。

### “部分覆盖”是什么意思？

“部分覆盖”表示 Profiler 只能统计自身挂载之后发生的生命周期事件。页面数据适合定位插件之间的相对性能差异，但不能当作整个 DSH 的完整冷启动时间。

### 无法读取性能数据怎么办？

如果页面显示“暂时无法读取性能数据”，说明插件前端已经加载，但暂时没有从 DSH Host 端取得性能快照。请依次尝试：

1. 完全关闭并重新启动 DSH
2. 在浏览器中按 `Ctrl + Shift + R` 强制刷新
3. 返回“设置 → 插件 → 性能”并点击“重试”
4. 如果仍然失败，查看启动 DSH 的 PowerShell 窗口，并将其中的错误信息提供给开发者

### 是否需要安装其他插件？

通常不需要额外安装普通功能插件。本插件依赖 DSH 自带的 Host、Remote 和 Typert 基础运行环境。如果“插件启动性能”页面能够显示，就说明本插件本身已经安装成功；读取失败通常发生在 Host Remote 注册或调用阶段。

## 开发

在插件目录执行：

```powershell
cd D:\DSH\Plugin\DSH-Plugin-Profiler
pnpm run check
```

`check` 命令会依次执行：

1. TypeScript 类型检查
2. 单元测试
3. Host 和 Client 构建
4. 构建产物验证

也可以按需要单独执行：

```powershell
pnpm run typecheck
pnpm run test
pnpm run build
pnpm run verify:build
```

### 启动 DSH

构建完成后，在 DSH 项目目录启动 Web 界面：

```powershell
cd D:\DSH\app
pnpm dsh web
```

修改源码后，需要重新构建并完全重启 DSH。浏览器仍显示旧界面时，请按 `Ctrl + Shift + R` 强制刷新。

## 工作方式

插件分为 Host 和 Client 两部分：

- Host 端监听 Cordis 生命周期事件并生成性能快照
- Typert 描述声明 `pluginProfiler/snapshot` Remote 接口
- Client 端读取快照，并在“设置 → 插件 → 性能”中展示结果

## 项目结构

```text
src/
├─ adapters/                 Cordis 生命周期适配
├─ client/                   设置页面和浏览器端入口
├─ core/                     性能采集器与状态机
├─ host/                     Host Remote 网关
├─ wire/                     数据结构和边界校验
├─ index.ts                  Host 插件入口
├─ typert.host.ts            Host Typert 描述
└─ typert.remote-client.ts   Client Remote 描述
```

## 当前状态

本项目仍处于开发阶段。当前数据适合定位插件之间的相对启动性能差异，但暂不能替代完整的 DSH 冷启动分析。
